# Мэдээллийн гурван давхарга: хэсгийн гарчиг → карт → дэлгэрэнгүй

(UI/UX grill, Майк сонгосон, Claude санал болгосон, 2026-11-17.) Зорилгын 5 асуулт ("Юу өсөж байна? Яагаад? Хэр найдвартай? Хэзээ?
Өмнө нь зөв байсан уу?") нэг картанд багтахгүй. Track record нь сэдэв бүрийнх биш, дүгнэлт/кодын түвшинд тооцогддог (ADR 0020),
тиймээс карт бүр дээр давтвал чимэглэл болно.

| Давхарга | Юу харагдах | 5 асуултаас |
|---|---|---|
| **1. Хэсгийн гарчиг** (нэг удаа) | Асуулт + огноо ("11.16-нд огцом өссөн 14 сэдэв: ирэх 3 өдөрт үргэлжлэх үү?"), track record-ын богино мөр, `сэргээж тооцсон · model vX` | Хэзээ, Өмнө нь зөв байсан уу |
| **2. Карт** (interaction-гүй, 5 секунд) | Сэдвийн нэр · `● огцом ×3` · дүгнэлт ба таамаг · жижиг spark (14 өдөр + 3 өдрийн таамаг band-тай, огцом өссөн өдөр ●) | Юу, чиглэл, хүч, итгэл |
| **3. Дэлгэрэнгүй** (дарахад / сэдвийн хуудас) | Нөхцөл байдлын код + тайлбар, 60 өдрийн гол график, replay, бүтэн icon array | Яагаад, Өмнө нь зөв байсан уу |

- Давхарга 2 нь ADR 0025-ийн "interaction-гүйгээр 5 секунд" шалгуурыг ганцаараа хангана.
- Нөхцөл байдлын код 3-р давхаргад: кодын 95% нь "Буцалт" (ADR 0020), карт бүр дээр гарвал давтагдана.
- Spark бүр ижил хэмжээтэй, сэдэв бүр өөрийн y-тэнхлэгтэй (хэв маягийг харуулна). Тиймээс spark дээр тоо бичихгүй, тоо нь текстэд.
- Spark бүрд дэлгэц уншигчид зориулсан `aria-label` текст байна.
- **Prototype-ийн шалгуур:** 3 өдрийн band ~375px картанд нүдэнд ялгарах уу. Ялгарахгүй бол карт дээр текст нөөц ("+5…+20%") гарна.

## Дэлгэрэнгүйг нээх товч (Майк сонгосон)

- "Яагаад?" биш. Нөхцөл байдал нь шалтгаан биш, ажиглагдсан нөхцөл ба түүний track record (ADR 0020, `CONTEXT.md`).
- **Prototype-д хоёр шошго:** "Ямар нөхцөлд?" / "Юунд үндэслэсэн бэ?" (сүүлийнх нь хэрэглэгчийн "яагаад"-д ойр, шалтгаан биш нотолгоо амлана). ~375px-д багтах эсэх.
- Дэлгэрэнгүйн доод талд үргэлж: "**Энэ нь таамгийн шалтгаан биш. Ийм үед өмнө нь юу болж байсныг харуулна.**"

## 3-р давхарга хоёр хуваагдана (Майк сонгосон)

| | Юу | Хаана |
|---|---|---|
| **3а. Дэлгэрэнгүй** | Нөхцөл байдлын код + 1–2 өгүүлбэр, тэр нөхцөлийн track record (icon array), доод талын тайлбар | Картын дотор, товчоор дэлгэгдэнэ |
| **3б. Сэдвийн хуудас** | 60 өдрийн гол график (band, ●, мөчлөгийн тэмдэг), replay, сэдвийн бүх түүх | `#/topic/<сэдэв>` |

- Replay зөвхөн 3б-д. ADR 0020-ийн "replay-ийн хажууд нэгдсэн track record үргэлж" дүрэм тэнд хэрэгжинэ.
- **Prototype-д хоёр хувилбар:** (1) зөвхөн сэдвийн нэр холбоос; (2) картын бүх хэсэг сэдвийн хуудас руу ("stretched link"), дэлгэх товч л үл хамаарна.
  Товчийг `<a>` дотор хийхгүй (HTML буруу, дэлгэц уншигчийг төөрөгдүүлнэ). Шалтгаан: spark дээр дарахад юу ч болохгүй бол эвдэрсэн мэт санагдана.
- Хоёуланд tap target ≥ 44×44px.
- **Prototype-д шийдэх:** 3а олон картанд зэрэг дэлгэгдэх үү, accordion байх уу.

## Хуудасны бүтэц (Майк сонгосон)

- **Цэс 4 хуудастай хэвээр:** Нүүр · Бүх сэдэв · Хэв маяг (ADR 0022) · одоогийн "Загвар" (нэр нь UI grill-д шийдэгдэнэ). Сэдвийн хуудас цэсэнд ордоггүй.
- **Бүтэн track record** (код/дүгнэлт бүрээр, хадгалсан ба сэргээж тооцсоныг тусад нь) одоогийн "Загвар" хуудсанд, skill score-той хамт.
  Хэсэг бүрийн гарчгийн богино track record мөрөөс тэнд холбоос очно.
- **Хуудас доторх дараалал:** эхлээд track record (icon array, "10-аас 6 · ердийн үед 10-аас 3"), дараа нь skill score / dumbbell.
  Энгийн хэрэглэгч эхнийх рүү л орж ирнэ, техникийн хэсэг нь сонирхсон хүнд.

## Хуудасны нэр (Майк сонгосон)

- **Цэс:** "Загвар" → "**Найдвартай байдал**". Өдөр тутмын хэлэнд "загвар" нь дизайн / template гэж уншигдаж, "Хэв маяг"-тай андуурагдана.
  "Нарийвчлал"-аас татгалзсан: `CONTEXT.md`-ийн "Чиглэлийн нарийвчлал" хэмжүүртэй мөргөлдөнө. "Хэр зөв бэ?" нь цэсний цорын ганц асуулт хэлбэр болно.
- **h1:** "**Таамаг өмнө нь хэр зөв байсан бэ?**" ("байдаг" биш: track record бол өнгөрсөн, одоо бүгд сэргээж тооцсон; "байдаг" нь ирээдүйн амлалт мэт уншигдана).
  W6a (#45)-ийн "Загвар хэр зөв таамагладаг вэ?"-г орлоно.
- **URL хэвээр:** `#/model`, `#/facts`. Slug нь UI-д харагддаггүй, хуучин холбоос эвдрэхгүй.
- **Prototype-ийн шалгуур:** цэсийг Onest font-оор, text zoom 150% / 200% үед ~375px-д хэмжинэ (⚠️ засвар: эхний хэмжилт CSS ачаалагдаагүй байсан тул буруу. `styles.css` + Onest-оор 100% zoom-д цэс **359 / 359px**, зай 0px. "Найдвартай байдал" 150px. Цэсний зүйл бүр 36px өндөр, 44px-ээс бага).
  Багтахгүй бол хоёр мөр / хэвтээ scroll / товчилсон нэрийн аль нь гэдгийг тэнд шийднэ.

## Нүүрний дараалал (Майк чиглэлийг баталсан, эцсийнхийг prototype-оос сонгоно)

Эхний дэлгэц (~375×700) **Anomaly хэсгээр** эхэлнэ (одоо h1 + 380px treemap эхний дэлгэцийг эзэлж, гол асуулт scroll-ын дараа гардаг).
Prototype-д хоёр хувилбар:
- **(а)** h1 → Anomaly хэсэг → Давж өсөх → "Долоо хоногийн хэвийн өсөлт" (хураасан) → treemap ("Бүх сэдвийн газрын зураг") доод хэсэгт.
- **(г)** Anomaly картуудын хажууд / доор **намхан treemap** (~150–180px, ~375px дэлгэцэд). Огцом өссөн сэдвийн нүд ●-тэй тодорно,
  карт ↔ treemap-ийн нүд холбоотой hover/tap (ADR 0025-ийн 1-р interaction-ийн өргөтгөл). Гол асуулттай өрсөлдөхгүй, "бүх уншилтын дунд хаана байна" гэсэн контекст.
- Хоёуланд нь эхний дэлгэцэд Anomaly-ийн **хэдэн карт багтаж байгааг** хэмжинэ.
- **Ангиллын картуудыг нүүрнээс хасах** нь prototype-д харж шийдэх зүйл ("Бүх сэдэв" ангиллын чип, эрэмбээрээ тэр үүргийг гүйцэтгэнэ).

## Сэдвийн хуудас (3б): нэг гол график (Майк сонгосон)

- **Нэг гол график**, анхны цонх **60 өдөр** (одоо `serve.py: TOPIC_DAYS = 180`) + 3 өдрийн таамаг + band. Дээр нь `60 хоног · 180 хоног` сэлгэгч.
  60 өдөр нь Anomaly ба "ердийн өдөр"-ийн суурь цонх (t−59…t−7, ADR 0017), ~8.5 долоо хоног тул мөчлөг харагдана. 180 хоног нь "өмнө нь ийм байсан уу" гэсэн асуултад.
- Band, ●, мөчлөгийн тэмдэг (ADR 0024, 0026), replay бүгд энэ график дээр.
- **3 tile хасагдана.** Графикийн дээр 2–3 мөр текст (давхарга 2-ийн карттай ижил хэлбэр) + 3а-ийн нөхцөл байдал.
- **Хүснэгт хураасан** "Хүснэгтээр харах" хэлбэрээр үлдэнэ: графикийн текст хувилбар (WCAG 1.1.1).
- **Replay зөвхөн 60 хоногийн горимд.** 3 өдрийн давхцал 180 хоногийн горимд (~375px-д багана ~1.7px) харагдахгүй. 180 горимд replay-ийн хяналт
  идэвхгүй, "60 хоногийн горимд харна" гэсэн тайлбартай. Replay-д өдөр сонгоход график 60 горим руу шилжинэ.
- **Prototype-д:**
  - Суурь цонх t−59…t−7: маш бүдэг дэвсгэрээр тэмдэглэсэн (tooltip: "ердийн түвшинг энэ хугацаагаар тооцсон, сүүлийн 7 хоногийг оруулаагүй") / тэмдэглээгүй.
  - 180 хоногийн горимд гар утсан дээр баганын оронд area / шугам. Дүүргэлтийн дүрэм хэвээр (бодит = дүүргэсэн, таамаг = судал / тасархай).
  - 60/180 сэлгэгчтэй / сэлгэгчгүй.

### Гол графикийн mark (Майк сонгосон)

- **Үндсэн: шугам + band.** Түүх = тасралтгүй шугам; таамаг = тасархай шугам + D-ээс D+3 хүртэлх нэг band. Багана хувилбар (одоогийн бүтэц) нь prototype-ийн **харьцуулалт**.
  Шалтгаан: band нь нэг дүрс (band = итгэл, ADR 0026); 60/180 горим, spark, гол график нэг mark-тай, горим солиход mark өөрчлөгдөхгүй.
- **Band-ийг хүчээр тэлүүлэхгүй.** h1, h2, h3 нь тусдаа model тул интервал үргэлж тэлэхгүй байж болно (h2 нь h1-ээс нарийн). Өгөгдөл ямар байна, түүнийг л зурна.
  Valid дээр h1 ≤ h2 ≤ h3 хэдэн хувь байгааг давтамжийн скрипт тоолно. Олон тохиолдолд тэлэхгүй бол "алс ирээдүй бага итгэлтэй гэдгийг үггүйгээр харуулна" гэсэн амлалтыг эндээс хасна.
  ✅ **Тоолсон (#54, 2026-11-25, `docs/numbers/frequency.md` #11):** (в)-гүй valid, хэмжигдэх 63,413 мөрийн **97.3%**-д pct өргөн
  h1 ≤ h2 ≤ h3 (h1 ≤ h2 99.2%, h2 ≤ h3 97.5%). Лог өргөн 0.256 < 0.351 < 0.395. **Амлалт хэвээр.** Үлдсэн 2.7% нь h бүрийн Δ̂ өөр
  тул (band-ийг хүчээр тэлүүлэхгүй, дээрх дүрэм хэвээр).
- **h1–h3 цэгүүдэд шинэ тэмдэг нэмэхгүй** (●, ■, tick, шошго хангалттай). Анхдагчаар тэмдэггүй, зөвхөн tap / crosshair үед тэр гурван цэг идэвхжинэ.
  Хоёр цэгийн хоорондох шугам нь интерполяци, таамаг биш. Өдөр бүрийн яг утга tooltip ба хүснэгтэд байна.

### Y тэнхлэг (Майк сонгосон)

- **Бүх горимд (60, 180) шугаман, 0-ээс.** Шугамын доорх area нь "тэгээс хэр их" гэсэн утгатай тул 0-ээс эхлэх нь заавал.
  0-ээс эхлэхгүй бол жижиг хэлбэлзэл "огцом" мэт харагдаж, ADR 0022-ийн өнгө аяс ба "огцом" (z ≥ 3) гэсэн үгийн утгыг эвдэнэ.
- **Лог тэнхлэг нэмэхгүй**, дэлгэрэнгүй горим болгож ч (нэг графикт хоёр масштаб андуурал нэмнэ).
- **Spark ч 0-ээс**, масштаб нь сэдэв бүрийнх.
- Оргилын дараах band нарийн харагдах нь үнэн дүр зураг (оргилтой харьцуулахад сэдэв бараг алга болж байгаа). Band-ийн утга tooltip ба хүснэгтэд.
- **Prototype-д:** ×10-аас дээш оргилтой бодит сэдвийг 60 горимд харж, оргилын дараах band ~375px-д хэдэн пиксел болохыг хэмжинэ.
  Хэт нарийн бол графикийн дээрх текст мөр (дүгнэлт + тоо + интервал) ганцаараа хариулт өгч чадаж байгааг шалгана.

## Цэс гар утсан дээр (Майк сонгосон)

- **Суурь: flex-wrap.** Багтвал нэг мөр, багтахгүй бол мөр шилжинэ (2×2). Зүйл бүр **≥ 44px** өндөр (одоо 36px). Zoom 200%-д ямар ч нэртэй байсан ажиллана (WCAG 1.4.10).
- Татгалзсан: хэвтээ scroll (сүүлийн зүйл нуугдана), mobile-д товчилсон нэр (нэг хуудас хоёр нэртэй).
- **Prototype-д харьцуулалт:** доод tab bar.
- "Эхний дэлгэцэд хэдэн Anomaly карт багтах" хэмжилтийг цэсний бодит мөрийн тоотой хийнэ.
- ⚠️ "Найдвартай байдал" нэрийн шийдвэр буруу хэмжилт дээр гарсан тул дахин нээгдсэн (доорх хэсэг).

### Цэсний нэр: "Нотолгоо" түр, expectation test-ээр эцэслэнэ (Майк, 2026-11-17)

- Сервер + `styles.css` + Onest, ~375px, 100% zoom: "Нотолгоо" 80px (зай 70px), "Өмнөх таамаг" 111px (39px), "Найдвартай байдал" 150px (0px).
  "Үнэлгээ" (дотоод evaluation гэсэн утгатай мөргөлдөнө), "Үр дүн" ("бодит үр дүн"-тэй мөргөлдөнө), "Гүйцэтгэл" (техникийн), "Найдвар" ("hope"), "Баталгаа" (хэт амлана) хасагдсан.
- **Түр сонголт: "Нотолгоо".** Эрсдэл: өдөр тутмын хэлэнд "нотлох баримт / математик нотолгоо" буюу "зөв болох нь батлагдсан" гэж уншигдаж болно. Хуудас харин хэр зөв, хэр буруу байсныг харуулна.
- **Эцэслэх:** Майк prototype шатанд 3–4 хүнтэй expectation test хийнэ ("Нотолгоо" / "Өмнөх таамаг" / "Найдвартай байдал").
  Асуулт, дараалал, шийдвэрийн дүрэм нь `docs/ui-tests/tsesnii-ner-expectation-test.md`-д, тестээс өмнө тогтоосон.
- h1 "Таамаг өмнө нь хэр зөв байсан бэ?" хэвээр. URL `#/model` хэвээр.

## Гар утсан дээрх interaction (Майк сонгосон)

- **Нэг tap = нэг үйлдэл.** Давхар tap ("эхний tap тодруулна, хоёр дахь нь шилжинэ"), long-press байхгүй.

| Элемент | Desktop | Гар утас (tap) |
|---|---|---|
| Treemap-ийн нүд | hover = холбоотой картыг тодруулна | Нүүрэнд карт нь байгаа бол тэр карт руу scroll + тодруулна, үгүй бол сэдвийн хуудас (prototype-д харьцуулалттай, доор) |
| Карт | hover = treemap-ийн нүдийг тодруулна | Сэдвийн хуудас (эсвэл зөвхөн нэр, prototype-ийн хувилбар) |
| "Ямар нөхцөлд?" товч | дэлгэх | дэлгэх |
| Графикийн ● | tooltip (огноо, ×N) | tooltip |
| Band / таамгийн хэсэг | tooltip "80% магадлалтай энэ хооронд" | tooltip |
| Графикийн бусад хэсэг | crosshair (хамгийн ойрын өдөр) | crosshair, гадна tap-аар хаагдана |

- Карт → treemap чиглэл гар утсан дээр **scroll-linked**: (г) хувилбарт treemap харагдаж байхад дэлгэцийн голд байгаа карт нүдээ тодруулна. `prefers-reduced-motion` үед хөдөлгөөнгүй, зөвхөн өнгө.
- Tooltip бүр Esc / гадна tap-аар хаагдана, keyboard focus-оор нээгдэнэ (WCAG 1.4.13).
- **Scroll-ийг булаахгүй:** tap (дарж тавих) = crosshair / tooltip; босоо чирэлт = хуудас гүйлгэх (`touch-action: pan-y`). Гол график, spark, treemap бүгдэд.
- **Prototype-д харьцуулалт:** treemap-ийн нүд **үргэлж** сэдвийн хуудас руу, карт ↔ нүдний холбоос зөвхөн scroll-linked тодролоор.
  Шалтгаан: нөхцөлөөс хамаарсан хоёр үр дүн (scroll / шилжих) ба хуудасны гэнэтийн үсрэлт чиг баримжааг алдагдуулж болзошгүй.
  Expectation test-д "энэ нүдийг дарвал юу болох вэ?" асуулт нэмэгдсэн.

## Ачаалж буй ба алдааны төлөв (Майкийн шаардлага, prototype-д заавал)

Сайт Render free дээр (ADR 0011): 15 минут хүсэлтгүй бол унтаж, сэрэхэд "~1 минут орчим" (ADR 0011, README; хэмжсэн тоо биш).
Тэгэхээр шинэ хэрэглэгчийн **анхны нээлт ихэвчлэн ачаалж буй дэлгэц** байна, 5 секундын шалгуур (ADR 0025) яг тэнд шалгагдана.
Одоо: `<p class="state">Ачаалж байна…</p>`, алдаа гарвал "Өгөгдөл ачаалж чадсангүй (…). Хуудсыг дахин ачаалж үзнэ үү." (`app.js: route`).

- **Cold start:** skeleton карт (давхарга 2-ийн хэмжээтэй, layout үсрэхгүй) + шударга мэдэгдэл, жишээ нь "Сервер сэрж байна, хагас минут орчим".
  Мэдэгдлийн хугацааг **бодит хэмжилтээр** бичнэ: ≥ 15 минут идэвхгүй болсны дараа ≥ 5 удаа нээж, HTML ба `/api/trending`-ийн хүлээлтийг (TTFB, нийт) тэмдэглэнэ.
  Хэмжилт хийгдэх хүртэл "хагас минут" гэсэн тоог ашиглахгүй. (2026-11-17-нд энэ cloud session-оос `trandviz.onrender.com` сүлжээний бодлогоор хаагдсан тул хэмжиж чадаагүй.)
  `prefers-reduced-motion` үед skeleton-ийн shimmer хөдөлгөөнгүй.
- ⚠️ **Нээлттэй эрсдэл:** HTML ба `/static/` нь мөн тэр унтдаг серверээс (`app/main.py`) ирдэг. Тэгэхээр cold start-ийн үед манай skeleton биш,
  browser-ийн хоосон дэлгэц / Render-ийн өөрийн хуудас харагдаж магадгүй. Prototype-д бодитоор юу харагддагийг screenshot-оор шалгана.
  Skeleton харагдахгүй бол HTML-ийг унтдаггүй static hosting-оос өгөх эсэх (API нь Render дээр үлдэнэ) гэсэн тусдаа шийдвэр гарна (ADR 0011-ийг өөрчилнө, Майк шийднэ).
- **Хэмжилт (2026-11-26, cloud session-оос, нэг удаа):** унтаж байсан `trandviz.onrender.com`-ийн `/` (HTML) эхний байт **43.9 секунд**,
  сэрсний дараа `/api/health` 0.6 секунд. Тэгэхээр дээрх ⚠️ эрсдэл бодит: cold start-ийн ~44 секундэд манай skeleton биш browser-ийн
  хоосон дэлгэц харагдана. Skeleton ба "N секунд болж байна" нь HTML ирсний дараах удаан API-д л ажиллана. HTML-ийг унтдаггүй static
  hosting-оос өгөх эсэх нь Майкийн шийдвэр хэвээр (ADR 0011). ≥ 5 удаагийн хэмжилт хараахан хийгдээгүй.
- **API алдаа:** юу болсныг энгийн үгээр ("Өгөгдөл ирсэнгүй. Сервер түр ажиллахгүй байж магадгүй."), **"Дахин оролдох"** товч (≥ 44px, хуудсыг бүтнээр биш зөвхөн
  хүсэлтийг давтана), техникийн код (HTTP статус) нь бүдэг жижиг текстээр. Нэг хүсэлт амжилтгүй болбол өөр хэсэг (жишээ нь treemap) ажилласаар байх эсэхийг prototype-д харна.

## Prototype-ийн сонголт (Майкийн шийдвэр, 2026-11-26)

Prototype-ийн 1-р шатыг (branch `claude/gracious-davinci-l04t7s`, throwaway, `main`-д merge хийхгүй) Майк үзэж шийдсэн. **2-р шат (theme) алгасагдсан** (ADR 0023).

- **Бүтэц: (а).** (г) (намхан treemap картын хажууд, карт ↔ нүдний scroll-linked холбоос) хасагдсан.
- **Нүүрний дараалал (Майкийн шийдвэр, 2026-11-26, cognitive load-ыг багасгах):** header-ийн доор нэг мөр h1
  ("11.10-нд огцом өссөн 27 сэдэв: ирэх 3 өдөрт үргэлжлэх үү, унтрах уу?"), **шууд дараа нь treemap** (түлхүүр
  "Хэмжээ = уншилт · ердийнхөөс ×1 … ×10+ · ● огцом өссөн"-тэй). Дараа нь "Үргэлжлэх төлөвтэй" / "Унтрах төлөвтэй" →
  "11.11–11.13-нд сэргэх төлөвтэй" → "Долоо хоногийн ердийн өсөлт" (хураасан). Дээрх "Нүүрний дараалал"-ын "Эхний дэлгэц Anomaly
  хэсгээр эхэлнэ"-г орлоно. Ангиллын картууд нүүрнээс хасагдсан. Эхний карт 390×844-д бүтнээрээ багтах зорилго хэвээр тул
  гар утсан дээр treemap намхан. Treemap ачаалахгүй бол картууд ажилласаар (хэсэг бүр өөрийн хүсэлттэй).
- **Нүүрэнд хэсэг бүрт top 3 карт, бүрэн жагсаалт "Бүх сэдэв" хуудсанд (Майкийн шийдвэр, 2026-11-26):**
  - "Үргэлжлэх төлөвтэй" ба "Унтрах төлөвтэй" хэсэг тус бүрт **3 карт**: ×N (огцом өсөлтийн хэмжээ) их нь эхэнд, тэнцвэл таамгийн pct-ээр.
    Гарчигт нийт тоо хэвээр ("Үргэлжлэх төлөвтэй (8)"), 3 картын доор "Бүгдийг харах (8) →".
  - 3-аас цөөн бол байгаагаа л. 0 бол картын оронд нэг мөр ("11.10-нд "үргэлжлэх" төлөвтэй сэдэв алга."), холбоосгүй.
    ("Өнөөдөр" гэж бичихгүй: өгөгдөл asof өдрийнх.)
  - **"Бүх сэдэв"** хуудсанд шүүлтүүр **Бүгд / Үргэлжлэх / Унтрах** ба эрэмбэ **Уншилтаар / Өсөлтөөр / Бууралтаар** (ADR 0013). Хоёул URL-д
    (`#/list?f=continue&s=views`), буцах товч ажиллана. Нүүрний "Бүгдийг харах" тухайн шүүлтүүртэйгээр нээнэ. Бүх карт нүүрнийхтэй ижил загвартай.
    Ангиллын хэсэг, чип (ADR 0013-ын 1–4-р зүйл) энэ хуудсаас хасагдсан.
- **Үг:** ADR 0019-ийн "Долоо хоногийн хэвийн өсөлт" → "Долоо хоногийн **ердийн** өсөлт": сайтын үгийн дүрэм (ADR 0014, `tests/test_words.py`)
  "хэвийн"-ийг хориглодог, "ердийн өдөр"-тэй нэг үг.
- **Давхарга 1 богиноссон:** зөвхөн h1 ("11.10-нд огцом өссөн 27 сэдэв: ирэх 3 өдөрт үргэлжлэх үү, унтрах уу?") + нэг мөр
  ("6 нь үргэлжлэх, 21 нь унтрах төлөвтэй", treemap-ийн доор). Нүүрнээс хасагдсан: track record-ын богино мөр ("Өмнө нь: model 'үргэлжлэх'… 10-аас 6…"),
  `сэргээж тооцсон · model vX` мөр, "Хэр зөв байсан бэ? →" холбоос, "Огцом уншилт сайн, муу гэсэн үг биш…" мөр (ADR 0022). "Сэргэх
  төлөвтэй" хэсгийн track record мөр ч мөн адил хасагдсан. Дээрх хүснэгтийн давхарга 1-ийн "track record-ын богино мөр, `сэргээж тооцсон · model vX`"
  ба "Хэсэг бүрийн гарчгийн богино track record мөрөөс тэнд холбоос очно" нь хүчингүй: track record зөвхөн "Загвар" хуудсанд (цэсэнд бий),
  мөн 3а-д (тэр нөхцөлийн icon array, эх сурвалжтай).
- **Variant panel-ийн бүх toggle-д UI grill-ийн анхдагч санал батлагдсан:** `● ×3`; "Ямар нөхцөлд?"; хүчтэй өсөлт `↗ +40%` тод;

  гол график шугам + band; суурь цонх t−59…t−7 бүдэг дэвсгэр; 60/180 сэлгэгч байна; 180 хоногийн горимд area; түүх/таамгийн зааг нимгэн

### "Загвар" хуудас: график түрүүлнэ, хүснэгт нөөцөнд (Майкийн шийдвэр, 2026-11-26)

Prototype-ийн "Нотолгоо" хуудас хүснэгт, текст хэт ихтэй, уйтгартай байсан. Зорилго: **уншиж биш, харж ойлгох**. Цэсний нэр "Загвар",
h1 "Таамаг өмнө нь хэр зөв байсан бэ?" хэвээр.

- **Дүрэм:** график бүр = асуулт хэлбэрийн гарчиг + нэг мөр гол дүгнэлт + жижиг саарал тайлбар (n, "сэргээж тооцсон", model). Урт догол мөр байхгүй.
- **Дараалал:**
  1. Гол график: "'Үргэлжлэх' гэвэл үнэхээр үргэлжилдэг үү?": model "үргэлжлэх" гэсэн үед vs ердийн үед, хоёр том харьцуулалт. Дүгнэлт
     тооноос үүснэ ("Ердийнхөөс 2 дахин олон удаа зөв").
  2. "'Унтрах' гэвэл унтардаг уу?": ижил загвар, жижиг. Ялгаа бага гэдгийг шударгаар: "Ихэнх нь ер нь унтардаг. Model-ийн нэмэр нь цөөн 'үргэлжлэх'-ийг олоход."
  3. "Таамаг өндөр байх тусам үнэхээр өсдөг үү?": таамгийн зурвас бүрээр (≤ −20% … ≥ +25%) бодит "өссөн" / "буурсан" хувь, шат шиг diverging.
  4. "Нөхцөл байдал бүрт юу болдог вэ?": нөхцөл бүрээр хэвтээ diverging bar (буурсан ← → өссөн), эрэмбэлсэн. n < 20 бол бүдэг + "тоо хангалтгүй".
  5. "Нэг жишээ": өнгөрсөн нэг өдрийн таамаг ба бодит үр дүн (replay мини график), өдрөө сэлгэнэ.
  6. "Техникийн хэсэг" (хаалттай, дарж нээнэ): өмнөх "Загвар" хуудасны графикууд өөрсдөө (алгоритмын харьцуулалт, skill score, dumbbell г.м.).
