# Таамгийн хажууд "шалтгаан" биш, нөхцөл байдал ба түүний track record-ыг харуулна

(grill-ээр Майк зөвшөөрсөн (Claude санал болгосон), 2026-11-17.) Тоо бүгд (в)-гүй valid, хэмжигдэх сэдэв дээр.

## Шийдвэр

Сэдэв бүрт ажиглагдах өгөгдлөөс гаргасан **нөхцөл байдлын код**-ыг харуулна: Мөчлөг, Буцалт, Оргилын дараах бууралт,
Нийт уншилтын нөлөө, Үргэлжилж буй өсөлт. Хажууд нь тэр кодын track record-ыг бичнэ ("ийм нөхцөлийн 10-аас 6 нь ...").
**"Model үүнээс болж ингэж хэлсэн" гэж амлахгүй.** Код нь model-ийн хариу үйлдэл үзүүлсэн нөхцөлийг дүрсэлдэг, model-ийн дотоод шалтгааныг биш.

## Яагаад SHAP биш

Rising-ийн 4,000 мөр дээр feature-ийг бүлэглэсэн SHAP-ийг туршсан. Тэргүүлэх бүлэг нь 90–93%-д "Сүүлийн өсөлт/уналт", **"Хуанли" бүлэг
Мөчлөгийн өсөлт дээр ч 0%**. Учир нь model амралтын өдрийн уналтыг `dow`-оор биш `growth_1`/`ratio_7`-оор хардаг. SHAP математикийн хувьд
зөв ч хүний ойлгох шалтгааныг нуудаг. Мөн тэргүүлэх бүлэг дунджаар эерэг хувь нэмрийн 52%-ийг л эзэлдэг. SHAP-ийг зөвхөн дотоод шалгалтад ашиглана.

## Model энгийн "уналтын гүн" дүрмээс илүү юу (null finding-ийг шалгасан)

Rising-ийн 95.5% нь анхаарал 7 хоногийн дунджаас ≥ 5% доогуур үед гардаг (бүх мөрийн 37.7% нь ийм байдаг). Тэгэхээр model бараг
зөвхөн буцалт таамагладаг. Гэхдээ энгийн дүрмийг давдаг:

| Давж өсөх жагсаалт, өдөр бүр ижил N ≤ 10 | Бодит илүүдэл ≥ +10% | Бодит ≥ +25% |
|---|---|---|
| **CatBoost** (ADR 0019) | **58.9%** | **31.1%** |
| Уналтын гүнээр, мөчлөг ≥ +10%-ийг хассан | 41.9% | 16.8% |
| Уналтын гүнээр, бүх сэдэв | 29.5% | 23.6% |
| Санамсаргүй (мөчлөггүй мөр) | 30.1% | 9.6% |

Rising ба "7 хоногийн дунджаас 20%+ доор" дүрэм ижил тооны мөр сонговол ердөө 23% нь давхцдаг. Буцалт дотор ч CatBoost илүү сайн
эрэмбэлдэг: өдөр бүрийн Spearman(эрэмбэ, бодит илүүдэл) нь 0.16, уналтын гүнийх 0.08.

### Буцалтын "ердийн түвшин рүүгээ буцна" дүрэмтэй харьцуулалт (#54, 2026-11-25)

Дээрх "уналтын гүн" дүрэм нь "хэр гүн унасан"-аар эрэмбэлдэг. Илүү хүчтэй энгийн дүрэм (#54-д "naive"; CONTEXT.md-ийн naive нь
Δ̂ = 0 тул энд **буцах дүрэм**): Δ̂ (h3) = ердийн түвшин − y_0 (28 өдрийн медиан, эсвэл ADR 0017-ийн t−59 … t−7-ийн медиан),
Давж өсөх жагсаалтын дүрмээр, өдөр бүр CatBoost-ийн жагсаалттай ижил N. CI = өдрөөр хос bootstrap (`docs/numbers/frequency.md` #12).

| **Буцалт мөрүүд дээр** | MAE (Δ, h3) | Бодит илүүдэл ≥ +10% | CatBoost − дүрэм |
|---|---|---|---|
| CatBoost | **0.152** | **59.1%** | |
| Буцах дүрэм, 28 өдрийн медиан | 0.224 | 54.3% | +4.7 pp (95% CI +2.0 … +7.3) |
| Буцах дүрэм, ADR 0017-ийн түвшин | 0.256 | 56.0% | **+3.0 pp** (+0.4 … +5.6) |
| Naive (Δ̂ = 0) | 0.166 | | |
| Үндсэн хувь (Буцалт доторх) | | 38.8% | |

Бүх хэмжигдэх мөрөөс (нүүрний жагсаалт шиг) бол CatBoost 58.9%, буцах дүрэм 51.8% / 51.6% (+7.1 / +7.3 pp), үндсэн хувь 29.3%.

- **Ялгаа бага.** Буцалт дотор CatBoost нь буцах дүрмээс 3–5 pp л илүү (CI 0-ээс дээш, доод хил +0.4 pp). Үндсэн хувиас (38.8%)
  дүрэм +16 pp, CatBoost +20 pp. Жагсаалтын үнэ цэнийн ихэнх нь "ердийн түвшнээсээ доош орсон сэдэв буцна" гэсэн энгийн баримтаас
  гардаг. Нүүрний "сэргэх төлөвтэй" хэсгийн шийдвэрт оролт (PLAN "Скриптийн дараа шийдэх"), Майк шийднэ.
- Цэгэн таамгаар (MAE) CatBoost хамаагүй сайн: буцах дүрэм бүрэн буцалтыг хэт их таамагладаг тул naive (Δ̂ = 0)-аас ч муу.

## Кодын тархалт (жирийн Rising, өдөрт 14.1)

Буцалт 13.4 (95%), тодорхой бус 0.56 (4%), Үргэлжилж буй өсөлт 0.14 (1%). Үүнд мөчлөгөөс эрс давсан Rising (0.7) орсон.

## UI хэлбэр (UI/UX grill, Майк сонгосон, 2026-11-17)

- **Өгүүлбэр + 10 дөрвөлжин icon array + үндсэн хувийн мөр.** Дөрвөлжин ■□ (● = Anomaly, сум = таамаг тул тэдгээрийг хэрэглэхгүй).
- **Үндсэн хувь заавал.** "10-аас 6" хаана ч ганцаараа гарахгүй. **"Санамсаргүй" гэж бичихгүй**, энгийн хэрэглэгч зоос шидэх (50%) гэж ойлгоно. Утгаар нь бичнэ:
  - Anomaly: `■■■■■■□□□□ model "үргэлжлэх" гэсэн үед` / `■■■□□□□□□□ ердийн үед (бүх огцом өссөн сэдэв)`.
    Картанд: "ийм таамгийн 10-аас 6 нь биелсэн (ердийн үед 10-аас 3)". (60.8% ба 30.5%, ADR 0021)
  - Давж өсөх жагсаалт: `■■■■■■□□□□ жагсаалтад орсон үед` / `■■■□□□□□□□ ердийн үед (бүх сэдэв, долоо хоногийн мөчлөгийг хассаны дараа)`.
    Картанд: "ийм таамгийн 10-аас 6 нь биелсэн (ердийн үед 10-аас 3)". (58.9% ба ~~30.1%~~ **29.3%**, доорх засварыг үз)
- **Шошго:** одоо бүгд сэргээж тооцсон тул `сэргээж тооцсон · model vX` (ADR 0015, 0026). Хадгалсан log-оос гарсан тоог тусад нь, холихгүй.
- Replay-ийн хажууд энэ нэгдсэн track record **үргэлж** харагдана. Сонгосон ганц өдрийг төлөөлөл мэт үзүүлэхгүй.
- ✅ **Засвар (#54, 2026-11-25):** Давж өсөх жагсаалтын үндсэн хувь = **29.3%** (бүх хэмжигдэх мөрийн бодит илүүдэл ≥ +10%;
  ADR 0019-ийн "29%", `evaluate.beyond_list_metrics`, track record-ын `base`). Хуучин **30.1% давтагдахгүй**: мөчлөгийн өсөлт биш мөр 29.6%, тэдгээрээс
  өдөр бүр ижил N санамсаргүй авахын хүлээгдэх утга 29.9%. Дээрх хүснэгтийн "Санамсаргүй (мөчлөггүй мөр)" мөр (30.1% / 9.6%) нь
  repo-д ороогүй нэг удаагийн санамсаргүй сонголт байсан бололтой. "10-аас 3" гэсэн текст хэвээр. Эх: `docs/numbers/frequency.md` #9.
  ⚠️ Майкт: картын шошго "ердийн үед (бүх сэдэв, долоо хоногийн мөчлөгийг хассаны дараа)"-г үгчлэн авбал хүрээ нь мөчлөгийн
  өсөлт биш мөр (**29.6%**) байж болно. Аль ч тохиолдолд "10-аас 3". Буцалт доторх үндсэн хувь (38.8%) нь PLAN-ы 2 дахь асуулт.

## Тодорхойлолт ба хэрэгжүүлэлт (#51, 2026-11-25)

⚠️ Кодын нарийн тодорхойлолт өмнө нь бичигдээгүй байсан. Доорх нь Claude-ийн санал: дээрх тархалтыг (жирийн Rising өдөрт 14.1,
Буцалт 95%) давтах ба Glossary-ийн утгатай таарахаар сонгосон. **Майк батлах ёстой.** Өөрчилбөл `src/situation.py` ба тест.

Код бүр asof өдөр ба түүнээс өмнөх өгөгдлөөс (y = log1p(анхаарал)), **энэ дарааллаар**, эхэнд таарсан нь (`src/situation.code`):

| # | Код | Нөхцөл |
|---|---|---|
| 1 | Нийт уншилтын нөлөө | asof өдөр Wikipedia-ийн нийт уншилт ердийнхөөс огцом зөрсөн (`anomaly.total_note`, \|z\| ≥ 4, ADR 0017). Тэр өдөр бүх сэдэвт. |
| 2 | Мөчлөг | таамаг мөчлөгийн өсөлт эсвэл бууралт (ADR 0019) |
| 3 | Буцалт | **Anomaly биш** (z < 3), анхаарал 7 хоногийн (t−6 … t, лог) дунджаас ≥ 5% доор (`ratio_7` ≤ log 0.95) |
| 4 | Оргилын дараах бууралт | сүүлийн 7 хоногт (t−7 … t−1) Anomaly өдөр (z ≥ 3) байсан, өнөөдрийн y нь тэр 7 хоногийн хамгийн их y-ээс доор |
| 5 | Үргэлжилж буй өсөлт | анхаарал 7 хоногийн дунджаас ≥ 5% дээр ба 3 өдрийн өмнөхөөс өндөр (`growth_3` > 0) |
| — | тодорхой бус | бусад |

- Буцалт Оргилын дараах бууралтаас **түрүүлнэ**: эсрэг дараалалд жирийн Rising-ийн Буцалт 83% болж ADR-ийн тархалтаас зөрдөг.
  Гэхдээ "Anomaly биш" нөхцөлтэй тул Anomaly сэдэв хэзээ ч Буцалт болохгүй ("ердийн түвшнээсээ доош унасан" гэсэн утгатай зөрчилдөнө).
- Valid ((в)-гүй, хэмжигдэх, 271 өдөр) дээр: жирийн Rising өдөрт **14.09**, үүний Буцалт **94.5%**, тодорхой бус **4.1%**,
  Үргэлжилж буй өсөлт **0.9%**, Нийт уншилтын нөлөө 0.3% (дээрх 95 / 4 / 1-тэй таарна). Anomaly-ийн 54% Оргилын дараах бууралт,
  40% Үргэлжилж буй өсөлт, 5.5% Мөчлөг (`tests/test_situation.py`).

**Track record** (`src/situation.track_record`, `src/track_record.py` → `app/data/track_record.json` → `/api/track-record`):

- Хүснэгт: код бүр, таамгийн зурвас бүр (≤ −20%, −20…−10%, ±10%, +10…+25%, ≥ +25%, сайтын сумтай нэг хил), "үргэлжлэх/унтрах" бүр.
  Мөр бүрт n, бодит ≥ +10%, бодит > 0, бодит ≤ −10%, бодит илүүдэл ≥ +10% (бодит үр дүн h3 өдөр, ADR 0021). Дүгнэлтийн мөрөнд
  мөн `hit` (биелсэн хувь) ба `base_hit` (бүх Anomaly-ийн ижил үр дүн = "ердийн үед").
- Хүрээ: хэмжигдэх, (в)-гүй, бодит үр дүн мэдэгдсэн таамаг. **n < 20 бол тоо биш "хангалтгүй".** "Ердийн үед" (`base_hit`) ч мөн:
  Anomaly 20-иос цөөн бол null. Илүүдлийн хувь нь мөчлөг мэдэгдсэн мөрүүд дээр, тэдгээр нь 20-иос цөөн бол null.
- ⚠️ Майкт асуух: дүгнэлт нь бүх Anomaly-д (хэмжигдэхгүй, (в) сэдэвт ч) гардаг, харин `verdict_track` нь хэмжигдэх, (в)-гүй
  хүрээнээс. Хэмжигдэхгүй сэдвийн картанд track record-ыг харуулах уу (W7)?
- Эх сурвалж бүр (сэргээж тооцсон = `data/backtest/<хувилбар>/backtest.parquet`, хадгалсан = forecast-log-ийн `forecasts/*.json`)
  ба model хувилбар бүр **тусдаа хүснэгт**. Хоёр хувилбарыг нэг хүснэгтэд оруулбал `ValueError`. Хадгалсан log нь #51-ээс хойш
  тэр өдөр харуулсан код ба дүгнэлтийг хадгалдаг (хожим дахин тооцохгүй). `was_missing` боловч тэр өдрийн мөр хожим ирсэн
  таамгийг оноонд оруулахгүй (ADR 0016, 5-р зүйл). Forecast-log branch одоогоор хоосон тул хадгалсан хүснэгт хараахан алга.
- API: сэдэв бүрт `situation`, `situation_label`; Anomaly-д `verdict`, `verdict_label`, `verdict_track` (ачаалсан model
  хувилбарын сэргээж тооцсон хүснэгтээс); `/api/trending`-д `anomalies` = {n, continue, fade, all_fade}. "Бүгд унтрах" өдөр
  (жишээ нь 2025-11-16: 19 anomaly, "үргэлжлэх" 0) anomaly-ууд "унтрах" дүгнэлттэй хэвээр, `all_fade: true`.
- Дахин үүсгэх: `python -m src.backtest run` → `python -m src.track_record build [--log-dir <forecast-log checkout>]` →
  `python tests/golden/make_golden.py`.
