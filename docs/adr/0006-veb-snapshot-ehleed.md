# Вэб урьдчилан тооцоолсон JSON-оос уншина, гар snapshot-ыг эхэлж, cron-ыг дараа нь

Сайт хүсэлт бүрт Wikimedia руу хандахгүй, урьдчилан тооцоолсон JSON-ийг (mock-той ижил бүтэцтэй, `app/data/`) л уншина.
Ингэснээр Wikimedia API унасан ч сайт унахгүй. **Cron хэзээ ч ажиллахгүй байсан ч сайт байх ёстой** тул эхлээд гар snapshot
хийж, deploy хийгээд, сайт ажиллаж байгааг шалгана. GitHub Actions cron бол дараа нь хийх бонус. (Майк, 2026-11-09)

**Хүчингүй болгосон:** "app эхлэхэд / өдөрт нэг удаа сүүлийн 60 хоногийг Wikimedia-аас татаж таамаглах" гэсэн хуучин загвар.
Хоёр шалтгаантай: (1) хүсэлтийн замд гадны API орж ирнэ; (2) `level_365` нь 365 хоногийн медиан тул 60 хоногоор тооцвол
сургалтынхаас өөр утга гарч, train/serve зөрүү үүснэ. Snapshot, cron хоёулаа **≥ 400 хоног** татна.

## Дараалал

1. **Лхагва:** гар snapshot гаргаж (`app/data/*.json`), Hugging Face Spaces (Docker + FastAPI) руу deploy хийж, сайт ажиллаж байгааг шалгана.
2. **Тэгээд л (бонус):** GitHub Actions cron (~19:00 UB). Шинэ JSON-ийг commit хийгээд Space руу push хийнэ (`HF_TOKEN` secret).

## Дүрэм

- **User-Agent:** `Shuugian/1.0 (https://github.com/Monho12/trandVIZ)`. Wikimedia тайлбартай UA шаарддаг, байхгүй бол 403 өгнө. И-мэйл бичихгүй.
- **D өдөр хараахан гараагүй** эсвэл тэр өдрийн `total_views` дутуу бол cron ~3 цагийн дараа **нэг удаа** дахин оролдоно.
  Тэгээд ч болохгүй бол бууж өгч, сүүлийн амжилттай JSON-ийг хэвээр үлдээнэ.
- **Огноо:** вэбэд "ирэх 3 өдөр" биш тодорхой огноогоор ("11/11–11/13") бичнэ. Мөн өгөгдлийн **asof** огноог
  ("Өгөгдөл: 11/10 хүртэл") харуулна. Wikimedia D өдрийг D+1-нд гаргадаг тул h1 нь ихэвчлэн "өнөөдөр" болно.
- **Хоцролт:** asof нь 2-оос олон өдрийн өмнөх бол шар анхааруулга гарна.
- **Пүрэв:** үнэгүй Space унтдаг бөгөөд сэрэхэд 30+ секунд зарцуулдаг тул хамгаалалтаас 5 минутын өмнө нээж сэрээнэ.
