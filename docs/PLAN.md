## Мягмар 11/10 — загвар ба үнэлгээ

**Зорилго:** гурван алгоритмыг сургаж, valid-аар сонгоод, test-ийг нэг удаа үнэлж, вэбэд экспорт хийх.

1. **✅ Causal trim хийгдсэн (ADR 0007, PR #12). Дахин хийхгүй.** Үр дүнг ADR 0007-ийн "Үр дүн" хэсгээс үзнэ.
   `features.parquet` байхгүй бол `python -m src.clean && python -m src.features && python -m src.baselines`-аар үүсгэнэ.
   Бэлтгэл: хэрэгтэй бол `pip install --break-system-packages xgboost catboost`. Үргэлжлүүлэхээс өмнө `pytest -q` ногоон байх ёстой.
2. **Сургалт** (`src/train.py` + `notebooks/04_model.ipynb`, монгол тайлбартай, богино).
   LightGBM, XGBoost, CatBoost-ыг h1, h2, h3 тус бүрт тусад нь сургана. 18 feature, objective L1.
   **Hyperparameter optimization-ийг Optuna package-аар хийнэ. Энэ бол хичээлийн шаардлага**, тиймээс алгасах эсвэл гараар тааруулахгүй.
   TPE + MedianPruner, алгоритм бүрт ~25 trial, хурдасгахын тулд train-ийн 2023-07-01-ээс хойшх хэсэг, early stopping 100.
   Цаг дутвал h1 дээр тааруулсан параметрийг h2, h3-т дахин ашиглаж болно, гэхдээ notebook-д заавал тэмдэглэнэ. Optuna-ийн study (trial-ууд, шилдэг параметр) notebook-д харагдах ёстой.
   (Тохиргоог Майк зөвшөөрсөн (Claude санал болгосон), 2026-11-10.)
3. **Сонголт.** Зөвхөн **valid MAE-ээр, (в)-г хассан valid дээр**. Test-ийг сонголтод **огт** ашиглахгүй.
4. **Overfit.** Сонгосон алгоритмын train/valid learning curve, гурван алгоритмын train/valid MAE хүснэгт.
5. **🔥 босго T** (ADR 0004). (в)-гүй valid дээр, хэмжигдэх сэдвүүдийн хүрээнд: таамагласан pct(h3) = expm1(y_0 + Δ̂) / x_0 − 1-ийн квантилиуд.
   **T = 25% үед өдөрт дунджаар хэдэн 🔥 гарах вэ** гэдгийг тайлагнана. T = max(өдөрт ~5–10 гаргах босго, 25%).
6. **80% интервал.** Сонгосон алгоритмын **(в)-гүй** valid residual-ийн 10% ба 90%-ийн квантил, h бүрээр. Ингэвэл сонголт болон T-тэй ижил өгөгдөл ашиглагдана. (Майк зөвшөөрсөн (Claude санал болгосон), 2026-11-10.)
7. **Test үнэлгээ — НЭГ удаа.** Доорх "04_model-ийн үнэлгээ" хэсгийн бүх хэмжүүрийг **(а)/(б)/(в) тус бүрт**, загвар болон
   naive, seasonal, **momentum** baseline бүрт гаргана (чиглэл = sign(y_0 − y_{−3}), top-10 = x_0/x_{−3} − 1-ээр эрэмбэлсэн):
   MAE + skill score; precision@10 (h3) + momentum + үндсэн хувь; чиглэлийн нарийвчлал **ӨСӨХ ба БУУРАХ тусад нь**;
   MAE < naive байсан өдрийн хувь. ADR 0002-ийн шалгуурыг давсан эсэхийг дүгнэнэ. Гол дүгнэлт **(а)** дээр хийгдэнэ.
   (б)-ийн "↓" хэт сайн харагдана (оргилын дараах уналт). (в) нь сонголтын хазайлттай. Эдгээрийг гол дүгнэлт болгохгүй.
   Нэмээд: **skill score-ийн 95% bootstrap итгэх интервал** (өдрөөр нь resample хийж, ~1000 удаа) ба **80% интервалын бодит хамралт** test дээр (h бүрээр, зорилго 80%).
   `docs/hamgaalalt.md`-ийн `[тестийн дараа]` гэсэн хоосон зайг эдгээр тоогоор бөглөнө.
8. **Экспорт.** `app/model/` доор сонгосон алгоритмын 3 model + `meta.json`
   (algo, 18 feature, квантилиуд, T, бүх хэмжүүр бүлгээр, learning curve, importance top10).
9. **"Загвар" хуудас.** `app/mock/model.json`-ийг `meta.json`-оос бодит тоогоор шинэчилнэ. Одоогийн карт, өнгө, фонтыг хэвээр нь ашиглаж, Playwright-аар шалгана.
   Харуулах зүйл: 3 алгоритм + naive-ийн **(а) бүлэг дээрх test MAE-г хувиар**, ялагчийг тодруулж, skill score-ийг нэг мөрөөр. (Майк зөвшөөрсөн (Claude санал болгосон), 2026-11-10.)

**Майкд хэлэх:** ялагч алгоритм, (а) дээрх skill score, precision@10-ийг momentum ба үндсэн хувьтай харьцуулсан дүн, ӨСӨХ-ийн чиглэл, T ба өдөрт хэдэн 🔥, overfit + screenshot.

## 04_model-ийн үнэлгээ (grill-ээр Майк зөвшөөрсөн (Claude санал болгосон), 2026-11-09 — ADR 0001–0005, 0007)

Загвар, target (`y_h − y_0`, y = log1p(анхаарал)), L1 loss, хуваалт **өөрчлөгдөхгүй**. Feature нь **18** ширхэг: `category`-г хассан (ADR 0005), `feature_list.json`-оос уншина. Доорх зүйлс бол зөвхөн үнэлгээ ба хувиргалт.

**Хувь руу хувиргах (ADR 0003).** x = анхаарал. Таамаг x̂_h = expm1(y_0 + Δ̂), pct = x̂_h / x_0 − 1. Бодит утга мөн адил: x_h / x_0 − 1.
L1 нь медианыг таамагладаг тул bias засвар хэрэггүй, 80% интервалыг ч мөн expm1-ээр шууд хувиргана.

**Тодорхойлолт.**
- Үнэн trend: бодит pct (h3) ≥ +25% бол ↑, ≤ −20% бол ↓, бусад нь тогтвортой.
- Хэмжигдэх сэдэв: сүүлийн 7 хоногийн дундаж анхаарал **x хуваарьт** ≥ 1 (`roll_mean_7` нь log1p хуваарьт тул түүнийг ашиглахгүй).
- Momentum baseline (тогтмол, ADR 0002): чиглэл = sign(y_0 − y_{−3}), top-10 = **pct_m = x_0 / x_{−3} − 1**-ээр эрэмбэлсэн (загвартай ижил хуваарь).

**Leakage, сонголтын хазайлт (ADR 0005).**
- `category`-г загварт **оруулахгүй** (feature 18). `tests/test_features.py` үүнийг шалгана. 03-ыг дахин ажиллуулбал `pytest -q` хийнэ.
- Бүлгүүдийг `viral_articles.csv`-ийн `peak_month`-аар тодорхойлно: (а) сонгосон 151, (б) хуучин вирал ≤ 2025-06 (114), (в) шинэ вирал ≥ 2025-07 (36).
- **Алгоритм сонгох valid MAE болон T-г тааруулахад (в)-г хасна.** Харин **сургалтад (в) орно** (ADR 0009).
- **Хуваалтын хил дээр 3 хоногийн purge** хийнэ: t+3 нь мөрийнхөө хуваалтаас гарвал тэр мөрийг хасна (`purge_split_boundary`, ADR 0009).
- Test-ийн бүх хэмжүүрийг, загвар болон naive, momentum бүгдийг, **(а)/(б)/(в) бүлэг тус бүрт** тайлагнана. Гол дүгнэлт нь (а).
  (б)-ийн "↓" чиглэл хэт сайн харагдана (оргилын дараах уналт), (в) нь сонголтын хазайлттай. Эдгээрийг гол дүгнэлт болгохгүй.

**Тайлагнах (valid нь (в)-гүй, тэгээд test нэг удаа).** Алгоритм сонгох шалгуур нь зөвхөн valid MAE ((в)-г хассан).
1. MAE (лог, **бүх мөр**), h1/h2/h3. Харьцуулах нь naive, seasonal. Skill score = 1 − MAE/MAE_naive.
2. precision@10 (h3, хэмжигдэх сэдэв): өдөр бүрийн таамагласан pct-ээр top-10 сэдвийн хэдэн хувь нь үнэн ↑ болсон бэ, өдрүүдийн дундаж.
   Хажууд нь momentum-ийн precision@10 болон **үндсэн хувь** (тухайн өдөр хэмжигдэх сэдвүүдийн ↑-ийн эзлэх хувь).
3. Чиглэлийн нарийвчлал (хэмжигдэх сэдэв): **ӨСӨХ** (бодит pct ≥ +25%) ба **БУУРАХ** (≤ −20%) мөрүүд дээр **тусад нь**, загвар ба momentum.
4. Найдвартай байдал: test-ийн өдрүүдийн хэдэн хувьд загварын MAE < naive байсан бэ (h бүрээр).
5. 🔥 босго: valid ((в)-гүй) дээрх таамагласан pct (h3)-ийн тархалт (квантилиуд). **T = 25% үед өдөрт дунджаар хэдэн 🔥** гарах вэ.
   T = max(өдөрт ~5–10 гаргах босго, 25%). Сонгосон T-г `app/model/meta.json`-д хадгална.

**Амжилтын шалгуур (test-ээс өмнө тогтоосон, ADR 0002).**
- Skill score: цэгэн үнэлгээ ≥ 5% **ба** bootstrap-ийн 95% CI-ийн доод хил > 0 (h1, h2, h3 бүрт).
- precision@10 > momentum.
- **Гол шалгуур:** ӨСӨХ мөрүүдийн чиглэлийн нарийвчлал > momentum.
- Шалгуур давахгүй бол нуухгүй, слайдад шалтгаантай нь харуулна.

## Вэбийн харагдах байдал (ADR 0003, 0004) — дизайн хэвээр, зөвхөн текст, тоо

- Гол тоо нь h3-ын pct, 5%-д дугуйлна. +300%-иас их бол "↑ 3×-ээс их". Хажууд нь 80% интервалыг саарлаар бичнэ. h1, h2 нь графикийн шугам дээр.
- Сум: ≥ T бол 🔥, +10%…T бол ↗ x%, ±10% бол ≈ тогтвортой, −10…−20% бол ↘ x%, ≤ −20% бол ↓ унаж байна.
- Top-10 үргэлж дүүрэн, хэмжигдэх сэдвээс бүрдэнэ. Нам гүм өдөр 🔥 огт гарахгүй байж болно.
- "Бүх сэдэв" хуудсанд жижиг сэдэв pct-ээ харуулна, гэхдээ 🔥 авахгүй.
- Вирал сэдвийн ангиллыг "Бусад" гэж харуулна (ADR 0005).
- "Уншилт" биш "анхаарал" гэж бичнэ. Tooltip: "Wikipedia-ийн нийт уншилтад эзлэх хувь".

## Model сайтын ард ажиллах ба deploy (ADR 0008, 0006-г орлоно; байршуулалт ADR 0010)

- Майкийн шаардлага: *"the model must be deployed behind the website."* Байршуулалт: хамгаалалт дээр local (ADR 0010; HF Docker Space төлбөртэй болсон).
- FastAPI эхлэхдээ model-ийг ачаалж, хүсэлт бүрт inference ажиллуулна. Wikipedia-г өдөрт нэг удаа татаж cache хийнэ, API унавал сүүлийн cache ашиглана.
- `/api/model` нь ачаалагдсан алгоритмыг харуулна.
- User-Agent нь `Shuugian/1.0 (https://github.com/Monho12/trandVIZ)`, и-мэйлгүй. D өдөр гараагүй бол ~3 цагийн дараа нэг удаа дахин оролдоно.
- Вэбэд тодорхой огноо болон asof бичнэ. asof нь 2-оос олон өдрийн өмнөх бол шар анхааруулга гарна.
- Дараалал: `uvicorn` → local Docker → Playwright-аар шалгах. Token, нууц үгийг repo-д оруулахгүй.
